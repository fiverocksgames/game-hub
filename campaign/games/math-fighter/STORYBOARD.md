# Math Fighter Standalone Promo — Storyboard

## Format

- Working master: 20–25 seconds
- Primary composition: vertical-first 9:16
- Source footage: real gameplay capture
- Purpose: explain the core mechanic quickly, then accelerate into action

## 0:00–0:02 — Immediate hook

### Visual
Open on active gameplay, not a logo.

A readable arithmetic problem is already visible while three enemies descend with three different answer values.

### Edit
Hold just long enough for the viewer to notice that the enemies are answers, not generic targets.

### Optional copy
**정답을 찾았다면—**

Avoid adding a separate fake equation outside the game UI unless production testing shows the in-game problem is unreadable in 9:16.

## 0:02–0:06 — The decision

### Visual
The correct answer is on a different horizontal zone from the player's current ship position.

Show the player selecting/tapping that zone. If raw screen capture does not make the tap legible, add a restrained touch indicator in post-production rather than changing the game UI.

The ship begins moving into the selected zone.

### Copy
**정답을 고르는 게 아니라**

### Production intent
This is the most important explanatory beat. Do not cut directly from the arithmetic problem to firing.

The audience must see that the calculation determines a movement/targeting choice.

## 0:06–0:09 — The payoff

### Visual
The ship reaches the selected zone and fires.

Bullets hit the correct answer-bearing enemy. The target is destroyed and the current quiz/wave resolves.

### Copy
**정답을 격추한다.**

### Sound
Emphasize three distinct beats:

`tap/decision -> weapon fire -> correct-target impact/clear`

## 0:09–0:15 — Rule understood, pace accelerates

### Visual
Cut through two faster interactions.

Each mini-beat should preserve the same logic:

`problem -> correct enemy -> movement -> fire -> clear`

The first can use a nearby zone; the second should require a larger left/right movement if the build and capture allow it.

### Copy options
Use very little copy here.

Possible rhythmic words:

**계산. 판단. 이동. 격추.**

or no copy if gameplay is sufficiently readable.

### Edit
Now cuts can become much faster because the first interaction already taught the rule.

## 0:15–0:19 — Pressure / skill beat

### Visual
Show a more pressured moment:

- enemies lower on screen,
- faster decision,
- ship crossing zones,
- sustained fire or a Challenge-mode beat if verified in the capture build.

A brief danger moment is acceptable, but avoid making the game look primarily punitive.

### Copy
**생각하는 순간도 전투다.**

This line is optional and should be tested against the simpler gameplay-first edit.

## 0:19–0:22 — Final successful hit

### Visual
Land on the cleanest and most satisfying correct-target destruction from the capture session.

Use the impact as the transition into the end card.

### Audio
Let weapon/impact sound resolve before brand music settles.

## 0:22–0:25 — End card

### Visual
Math Fighter title/logo or approved title treatment.

FiveRocks Games branding can appear secondary.

### Copy
Primary candidate:

**Find the answer. Hit the target.**

Korean alternative:

**정답을 찾아, 격추하라.**

CTA should match the actual public/playable state confirmed immediately before delivery.

Do not show a store/download/play CTA that is not valid for the production build being advertised.

## Cutdown hypothesis

### 15-second

Likely structure:

- 0–2 problem/enemies
- 2–5 choose zone
- 5–7 fire/clear
- 7–12 two rapid interactions
- 12–15 title + CTA

The 15-second version must retain at least one complete decision chain.

### 6-second bumper

Do not try to explain the full game from zero if testing proves six seconds insufficient.

Working structure:

`problem + answer enemies -> tap/move -> correct hit -> Math Fighter`

Possible line:

**정답을 찾아, 격추하라.**

## What this storyboard is testing

This pilot intentionally tests whether a standalone FiveRocks ad can follow this pattern:

`show the real problem -> expose the player's decision -> show physical game action -> show consequence -> accelerate only after comprehension`

The postmortem should determine whether this pattern is reusable beyond Math Fighter rather than assuming that it is already a standard.
